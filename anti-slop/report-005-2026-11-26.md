# Bottom navigation and dock correction

Reported from an iPhone screenshot: Review showed page text between the price dock and floating navigation, with a glitch when changing tabs.

Root cause: the dock used a 90px-plus inset reservation while the actual navigation occupied 57px plus its bottom offset. Browser reproduction showed a 14px gap with no device inset; the mismatch grew with an iPhone safe area. Root View Transitions also snapshotted the fixed navigation while its selection pill was animating independently.

Fix: shared navigation-height and bottom-offset variables now derive the dock reservation. A white underlay joins the dock to the floating navigation, keeping content out of that region. The existing narrow-screen bar height remains supported. Keyboard mode suppresses the underlay with the hidden navigation. View Transitions now capture only #app, leaving fixed navigation live. Consecutive navigation requests skip the prior transition and discard stale callbacks. The existing black/lime appearance and liquid selection pill remain.

Verification: npm test passed. Chrome rendered checks at 390px and 320px measured exactly 0px from dock bottom to navigation top, with no horizontal overflow. Simulated 34px bottom clearance also produced 0px gap. Rapid tab changes at 4x CPU slowdown settled on the final requested tab with no remaining navigation animations and no JavaScript console errors. Desktop Studio at 1280px retained the floating bar, no extra footer when controls were absent, and no overflow. Phone Review screenshot visually inspected. Real iPhone hardware remains untested.

Prices, package logic, request submission and Zoho were not changed.
